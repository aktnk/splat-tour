# 読み込み検証（spike）

富士山資料館の実データ（展示場メイン 500MB の PLY、土器 22MB の GLB など）を、Web公開向けに変換し、PC・スマホのブラウザでどこまで快適に表示できるかを計測するための一時的な仕組みです。本体（`src/`）の機能ではありません。結果をもとに、公開データの形式とサイズの上限を決めます。

データは手元のPCだけで扱います。変換後のファイルは `spike/assets/` に置かれ、git には入りません。

## 比較するデータの種類

| 種類 | 作り方 | 読み込み方 |
|---|---|---|
| `<名前>-sh3.spz` / `-sh1.spz` | splat-transform で SPZ に圧縮。SH（見る角度による色の変化）の次数を 3 / 1 にしたもの | 全体をダウンロードしてから表示 |
| `<名前>-sh3-lod.rad` / `-sh1-lod.rad` | Spark の build-lod で LoD（詳細度の階層）を事前計算 | 粗い全体を先に表示し、近くの詳細を順次ストリーミング（`paged`） |
| `<名前>-sh3-csplat-lod.rad` / `-sh1-csplat-lod.rad` | 上と同じ。ただし build-lod の軽い保存形式（`--csplat`）を使う。サイズ・メモリは減るが、精度が下がる可能性がある | 同上 |
| `<名前>-orig.glb` / `-opt.glb` | GLB の元ファイルと、gltf-transform で最適化（meshopt 圧縮 + WebP テクスチャ）したもの | 全体をダウンロードしてから表示 |

SPZ でも「読み込み時にLoD生成（lod: true）」にチェックを入れると、ブラウザ側で LoD を作ってから表示します。事前計算（RAD）との比較用です。

## 必要なもの

- Node.js 20 以上
- RAD を作る場合: Git と Rust（https://rustup.rs/ ）
  - 初回だけ Spark のソースを `tools/.cache/` に取得し、build-lod をビルドします（数分）。
  - Rust がなければ RAD はスキップされ、SPZ だけ作られます。

## 手順

### 1. 変換

```bash
npm install
npm run spike:convert -- "/path/to/main-hall.ply" --name main-hall
npm run spike:convert -- "/path/to/dogu.glb" --name dogu
```

- `--name` は表示用の名前です（ファイル名にも使います）。
- `--sh 3,1` で作る SH 次数を指定できます（既定は 3 と 1）。
- `--rad-encoding gsplat,csplat` で作る RAD の保存形式を指定できます（既定は両方）。`gsplat` は高精度（従来どおり）、`csplat` は軽量です。
- `--skip-spz` / `--skip-rad` で片方だけ作れます。
- 変換結果のサイズと所要時間は `spike/assets/variants.json` に記録されます。500MB 級の PLY では、RAD の変換に時間がかかることがあります。

### 2. 表示サーバーの起動

```bash
npm run spike:dev
```

- PC では http://localhost:5180 を開きます。
- スマホでは、PC と同じ Wi-Fi につないで、ターミナルに表示される `Network: http://192.168.x.x:5180/` を開きます。
  - 開けない場合は、PC のファイアウォールでポート 5180 を許可してください。

### 3. 計測

データごとに次を繰り返します。

1. 「データ」で選び、「読み込み」を押す
2. 表示されたら 10 秒ほど見回したり移動したりする
   - 何も見えないときは「中心へ移動」、上下が逆なら「上下反転」
3. 「計測値を記録」を押す

スマホでは、「解像度」を「端末の値」と「1」の両方で試してください。解像度は負荷に大きく効きます。

### 4. 結果の共有

記録は、PC の `spike/results/results.jsonl` に自動で追記されます（git には入りません）。スマホで計測した分も PC 側に保存されるので、スマホからコピーする必要はありません。

- 「計測値を記録」を押したときのほかに、読み込み開始から 3 秒・10 秒・30 秒の時点でも自動で記録します（`trigger` が `auto-3s` などになります）。途中でブラウザが落ちても、そこまでの記録は残ります。
- このファイルの中身と、見た目の所感（ぼやけ、欠け、ちらつき、発熱、落ちたかどうか）を共有してください。
- 画面の「結果をコピー」も使えます。スマホで http 接続の場合はクリップボードが使えないため、テキストが選択状態になります。

## 計測項目

| 項目 | 意味 |
|---|---|
| 準備完了まで | 読み込み開始から、表示できる状態になるまで |
| 最初の描画まで | スプラットが初めて画面に描かれるまで |
| 通信量 | サーバーが実際に送ったバイト数とリクエスト数。ストリーミングでは Range リクエストの回数も出ます |
| FPS / 最悪フレーム | 直近 1 秒のフレーム数と、直近 5 秒で最も遅かった 1 フレームの時間 |
| 描画スプラット数（視野内） | いま描いているスプラット数 |
| JSヒープ | Chrome 系のみ。Safari では「取得不可」 |

注意: 同じ Wi-Fi 内での計測なので、通信時間は実際の公開環境（モバイル回線）より短く出ます。モバイル回線での待ち時間は「通信量 ÷ 回線速度」で見積もってください（例: 20Mbps ≒ 2.5MB/秒）。ストリーミング（RAD）では、通信量が少ないほど体感が速くなります。
